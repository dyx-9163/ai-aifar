# P3：平台治理与规模化

## 1. 目标

P3 让代码 Agent 从单机可用能力演进为可评估、可审计、可配置、可运营的长期产品。

P3 不以增加模型权限为目标，而是确保能力升级后仍然可控、可解释并能持续改善。

## 2. 评测体系

### 2.1 代表性任务集

建立脱敏、可重复执行的本地评测仓库，至少覆盖：

- 代码解释。
- 小型缺陷修复。
- 跨文件功能修改。
- 编译错误修复。
- 测试失败定位。
- 脏工作树保护。
- 上下文压缩后的长任务。
- 图片输入和前端视觉验证。
- 安全拒绝和审批。

### 2.2 指标

- 任务通过率。
- 首次补丁通过率。
- 最终测试通过率。
- 无关文件修改率。
- 补丁应用失败率。
- 工具调用解析失败率。
- 重复工具调用率。
- 平均工具轮数、总耗时和 Token。
- 用户取消响应时间。
- 高风险操作拦截率。

### 2.3 评测原则

- 同一任务固定代码基线和验收脚本。
- 提示词、工具 Schema、模型参数和上下文策略分别版本化。
- 每次只改变一组变量，再对比结果。
- 速度或 Token 减少只有在质量不下降时才算优化。
- 不使用模型自评替代真实编译、测试和安全检查。

## 3. 可观测性

### 3.1 任务追踪

每个任务形成完整 Trace：

- 用户目标摘要。
- 模型配置版本。
- 指令和 Skill 来源。
- 工具调用序列。
- 审批和策略决策。
- 文件修改。
- 验证结果。
- 最终状态和失败原因。

### 3.2 隐私边界

- 默认不记录完整源代码和模型隐藏推理。
- 工具输入输出按类型脱敏和截断。
- 支持本地-only 观测。
- 导出 Trace 前明确显示包含的代码、路径和错误信息。
- 用户可配置留存周期并安全清理。

## 4. 策略中心

### 4.1 策略层级

```text
产品强制安全策略
  > 管理员策略
  > 用户全局策略
  > 工作区策略
  > 单次任务授权
```

低层级不能放宽高层级禁止项。

### 4.2 可配置项

- 允许的工作区根目录。
- 文件大小、搜索结果和命令输出限制。
- 命令类别和审批规则。
- 网络域名允许列表。
- 可用模型和并发数。
- 可用 Skill、插件和 MCP 服务。
- Artifact 和审计留存时间。
- 是否允许并行 Agent 和 worktree。

## 5. 插件和 Skill 治理

### 5.1 安装与来源

- 插件包需要身份、版本、来源和完整性信息。
- 安装前展示新增工具、网络、文件和凭据权限。
- 更新不得静默扩大权限。
- 支持禁用、固定版本和回滚。

### 5.2 运行隔离

- 第三方工具在独立进程或受限环境中运行。
- IPC 和网络调用有超时与大小限制。
- 插件崩溃不应导致主 Agent 数据损坏。
- 插件不能访问未授权工作区或其他插件凭据。

### 5.3 管理员控制

- 允许列表和禁止列表。
- 固定可信发布源。
- 禁止个人安装。
- 审计安装、更新、连接和调用行为。

## 6. 安全治理

### 6.1 威胁模型

至少覆盖：

- 仓库文件中的提示注入。
- 网页和工具结果中的提示注入。
- 路径穿越和符号链接逃逸。
- Shell 参数注入。
- 恶意补丁和供应链脚本。
- 凭据泄露到模型上下文或日志。
- 插件权限升级。
- 长任务重复执行有副作用操作。

### 6.2 防护

- 外部内容永远作为数据，不作为高优先级指令。
- 工具权限由客户端策略决定。
- 敏感操作采用明确审批和参数预览。
- 依赖下载和外部通信显示目标域名。
- 对补丁、命令和连接器结果进行审计。
- 安全策略失败时默认拒绝执行。

## 7. 性能与容量治理

### 7.1 本地模型容量

记录并控制：

- 可用并发槽位。
- 上下文窗口与输出预算。
- 首 Token 延迟和生成速度。
- GPU/CPU 模式和服务健康状态。
- 排队时间和取消响应。

代码 Agent 循环会增加请求次数，不能只按单次生成速度评估容量。

### 7.2 上下文成本

- 稳定前缀、项目规则和工具描述做去重。
- 工具说明按需暴露。
- 大文件按片段读取。
- 成功日志只保留摘要。
- 任务里程碑触发压缩，不在每轮无差别压缩。

### 7.3 资源上限

按任务配置：

- 最大模型轮数。
- 最大工具调用数。
- 最大运行时长。
- 最大命令并发。
- 最大 Artifact 大小。
- 最大重试次数。

达到上限时保存检查点并给出明确原因，不把资源耗尽伪装成任务完成。

## 8. 发布和兼容性

- 工具协议、任务状态和数据库迁移均需要版本号。
- 新客户端连接旧模型服务时应检测能力并降级。
- 数据库迁移支持前向升级，回滚边界在发布说明中明确。
- Windows、macOS、Linux 分别验证路径、Shell 和权限差异。
- 发布包不得包含模型文件、缓存、测试结果、数据库或密钥。

## 9. 运营界面

管理员或高级设置应能够查看：

- 能力和策略版本。
- 各工作区授权。
- 已安装 Skill、插件和连接器。
- 最近任务成功率和主要失败类型。
- 工具调用和审批统计。
- 本地模型容量和排队情况。
- 审计与 Artifact 存储占用。

普通用户界面只展示完成任务所需的信息，避免暴露不必要的治理复杂度。

## 10. P3 验收摘要

1. 固定评测集可重复运行并比较两个版本结果。
2. 任务 Trace 能还原工具、审批、修改和验证顺序。
3. 源代码、密钥和隐藏推理不进入默认遥测。
4. 管理员禁止项不能被工作区或任务授权覆盖。
5. 插件升级扩大权限时必须重新审批。
6. 达到资源上限时任务安全停止并保留可恢复状态。
7. 发布包扫描不包含运行缓存、数据库、模型和密钥。

详细条目见 [验收矩阵](05-acceptance-matrix.md)。
