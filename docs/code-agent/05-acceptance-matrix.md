# 代码 Agent 验收矩阵

## 1. 使用方式

本矩阵是架构验收基线。实施计划可以增加更细的测试，但不能删除这里的核心验收项。

状态定义：

- `Not implemented`：尚未实现。
- `Implemented`：代码完成，但未形成完整证据。
- `Verified`：自动化或人工验收证据完整。
- `Blocked`：存在明确外部阻塞，并记录原因。

设计文档生成时所有新增能力均默认为 `Not implemented`。现有相似能力不能在未验证新契约前直接标记为完成。

## 6. 发布门槛

### P0 发布门槛

- P0-01 至 P0-20 全部 `Verified`。
- 路径、命令、补丁、取消和脏工作树场景必须覆盖真实 Windows 环境。
- 至少一个真实工程完成“失败后修复再验证”的端到端任务。

### P1 发布门槛

- P0 仍保持全绿。
- P1-01 至 P1-14 全部 `Verified`。
- 重启恢复必须使用打包客户端验证。

### P2 发布门槛

- P2 能力按开关独立发布；未启用能力不得扩大权限面。
- 每个启用模块的对应条目全部 `Verified`。

### P3 发布门槛

- 评测、策略、审计和发布扫描必须纳入持续发布流程。
- 任何安全回归均阻止发布。
