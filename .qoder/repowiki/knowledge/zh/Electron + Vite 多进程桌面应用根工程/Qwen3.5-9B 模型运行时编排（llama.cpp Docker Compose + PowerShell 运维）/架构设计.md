模块由两层组成：`compose.yaml` 定义三个互斥的 Compose profile（`cpu`、`hybrid`、`gpu`），分别挂载 `../models/Qwen_Qwen3.5-9B-Q4_K_M.gguf` 与 `mmproj-Qwen_Qwen3.5-9B-bf16.gguf` 为只读卷，使用 `ghcr.io/ggml-org/llama.cpp:server` 或 `:server-cuda` 镜像并以 `--host 0.0.0.0 --port 8080` 启动服务，端口映射到宿主 `127.0.0.1:8080`；PowerShell 脚本层位于 `model-runtime/`，其中 `runtime-common.ps1` 集中封装所有共享能力——Compose 调用封装 `Invoke-ModelCompose`（固定 `-f compose.yaml -p ai-aifar-model --env-file .env`）、Docker CLI 包装 `Invoke-ModelDocker`、模型工件 SHA-256 校验 `Assert-ModelArtifacts`、端口占用检测 `Assert-ModelPortAvailable`、容器状态查询 `Get-ModelProjectContainerStates`、运行期所有权判定 `Get/Assert-ModelRuntimeOwnership`，以及按 `/health` → `/v1/models` → `/props` → `/slots` 顺序调用的健康快照 `Get-ModelRuntimeSnapshot`；`start-model.ps1`、`status-model.ps1`、`stop-model.ps1`、`verify-model.ps1` 作为入口仅调用这些函数，并在 GPU profile 启动失败时采集容器状态与日志，匹配 OOM/CUDA 错误模式后自动降级到 hybrid profile。依赖方向单向：入口脚本 → runtime-common → Docker/HTTP，不反向依赖 compose 文件。
