## 1. 使用的系统与工具

本仓库的配置系统由三层组成，分别面向不同的运行边界：

- **Docker Compose + `.env`**：用于启动独立的 Qwen3.5-9B 模型运行时（llama.cpp server），通过 `compose.yaml` 的 profiles（`cpu` / `hybrid` / `gpu`）切换硬件加速模式，并通过 `model-runtime/.env` 注入 `LLAMA_PARALLEL`、`LLAMA_CTX_SIZE`、`LLAMA_N_PREDICT`、`LLAMA_GPU_LAYERS_HYBRID` 等运行时参数。
- **Electron 主进程环境变量**：应用自身通过 `process.env` 读取少量关键配置，例如 `PRIVATE_AI_DESKTOP_USER_DATA`（自定义用户数据目录）、`VITE_CONFIG_NATIVE_IGNORE_WARNING`（构建期警告开关）。
- **TypeScript 常量 + 能力归一化**：本地 Qwen 连接地址、模型名、profile id 被集中声明在 `src/shared/localQwenIdentity.ts`，并由 `src/agent/localQwenProfile.ts` 组装为 `ModelProfileInput`；推理能力、并发限制、最大输出 token 等通过 `src/agent/modelCapabilities.ts` 中的 `normalize*` 函数做类型与范围校验并回退到默认值。

## 2. 核心文件

| 层次 | 文件 | 作用 |
|---|---|---|
| 模型运行时 | `model-runtime/compose.yaml` | 定义三个 Docker profile（cpu/hybrid/gpu），将 `.env` 中的 `LLAMA_*` 变量映射为 llama.cpp 命令行参数 |
| 模型运行时 | `model-runtime/.env`、`.env.example` | 实际与示例环境配置，包含并行度、上下文窗口、预测数、GPU layers |
| 模型运行时 | `model-runtime/runtime-common.ps1` | PowerShell 公共库：解析 `-p ai-aifar-model` 项目下的 compose 状态、端口占用、健康检查、SHA256 模型工件校验 |
| 模型运行时 | `model-runtime/start-model.ps1` | 入口脚本：按 profile 启动容器、健康等待、GPU 失败时自动回退到 hybrid |
| 应用配置 | `src/shared/localQwenIdentity.ts` | 硬编码本地 Qwen 身份：`http://127.0.0.1:8080/v1`、模型名 `Qwen3.5-9B`、profile id `local-qwen35` |
| 应用配置 | `src/agent/localQwenProfile.ts` | 将本地身份包装为 `ModelProfileInput`，附带 `qwenCapabilities()` 和默认 reasoning 设置 |
| 能力配置 | `src/agent/modelCapabilities.ts` | 能力与限制的归一化器：推理协议、并发上限、最大输出 token、reasoning effort 校验 |
| 限制常量 | `src/shared/modelProfileLimits.ts` | `DEFAULT_MAX_OUTPUT_TOKENS=2048`、`MAX_OUTPUT_TOKENS=32768` |
| URL 规范化 | `src/shared/modelProfileUrl.ts` | 对阿里云 DashScope `/compatible-mode` 路径做标准化 |
| 测试/CI 配置 | `tests/e2e/live-model.spec.ts`、`live-workspace.spec.ts` | 通过 `PRIVATE_AI_LIVE_MODEL_BASE_URL`、`PRIVATE_AI_LIVE_MODEL_NAME`、`PRIVATE_AI_LIVE_MODEL_API_KEY`、`PRIVATE_AI_LIVE_MODEL_E2E` 控制在线模型 E2E 测试 |
| 构建配置 | `forge.config.ts` | 通过 `process.env.VITE_CONFIG_NATIVE_IGNORE_WARNING` 关闭 Vite 原生模块警告 |

## 3. 架构与设计约定

### 3.1 模型运行时配置（外部服务层）

- 所有模型运行时参数集中在 `model-runtime/.env`，由 `runtime-common.ps1` 通过 `--env-file` 传给 `docker compose`。若不存在 `.env`，则回退到 `.env.example`。
- `compose.yaml` 使用 Docker Compose profiles 区分三种部署形态：`cpu`（`--n-gpu-layers 0`）、`hybrid`（`${LLAMA_GPU_LAYERS_HYBRID}`）、`gpu`（`--n-gpu-layers 999`）。三者都暴露 `127.0.0.1:8080`。
- `start-model.ps1` 在 GPU profile 启动失败且日志中出现 OOM/CUDA 错误时，自动 down 掉当前容器并回退到 hybrid profile，这是唯一一处带“降级策略”的配置分支。
- 启动前会校验两个模型工件（`Qwen_Qwen3.5-9B-Q4_K_M.gguf`、`mmproj-Qwen_Qwen3.5-9B-bf16.gguf`）的 SHA256 与文件大小，不匹配直接抛错。

### 3.2 应用内配置（Electron 进程层）

- 本地 Qwen 连接信息不以 `.env` 形式注入 Electron 进程，而是以 TypeScript 常量集中声明于 `src/shared/localQwenIdentity.ts`，再被 `localQwenProfile.ts` 消费。这样本地 profile 的身份是编译期常量，避免运行时拼串错误。
- 仅少数跨进程或平台相关配置走 `process.env`：用户数据目录（`PRIVATE_AI_DESKTOP_USER_DATA`）、命令解释器（`ComSpec`）、构建期警告开关。
- 模型能力（text/vision/streaming/concurrency/reasoning）通过 `modelCapabilities.ts` 的 `normalize*` 系列函数统一归一化，非法输入会被静默回退到默认值或抛出明确错误（如 reasoning effort 不在 `effortOptions` 中）。

### 3.3 配置验证与约束

- `modelCapabilities.ts` 中的 `validateReasoningSelection` 会在启用 reasoning 时校验：inputMode 必须支持、protocol 必须匹配（toggle→qwen，effort→openai）、effort 必须在 `effortOptions` 中。
- `modelProfileUrl.ts` 对阿里云 DashScope 的 `/compatible-mode` 路径强制追加 `/v1` 并清空 search/hash。
- `runtime-common.ps1` 通过 `Assert-ModelRuntimeOwnership` 保证固定项目 `ai-aifar-model` 下恰好有一个活跃容器绑定 `127.0.0.1:8080`，否则报错。

## 4. 约定与约束（描述性）

- 模型运行时参数一律通过 `LLAMA_*` 前缀的环境变量传入，新增参数应同时更新 `.env`、`.env.example` 和 `compose.yaml`。
- 本地 Qwen profile 的 provider 固定为 `openai-compatible`，baseUrl 固定为 `http://127.0.0.1:8080/v1`，任何修改需同步更新 `localQwenIdentity.ts` 及 `isLocalQwenServiceProfile` 判定逻辑。
- 最大输出 token 不得超过 `MAX_OUTPUT_TOKENS`（32768），低于 1 的值会被归一化为 `DEFAULT_MAX_OUTPUT_TOKENS`（2048）。
- 并发限制通过 `normalizeMaxConcurrency` 钳制在 `[1, maxLimit]` 范围内，默认上限 32。
- E2E 在线模型测试默认禁用，仅当 `PRIVATE_AI_LIVE_MODEL_E2E=1` 时启用，且可通过 `PRIVATE_AI_LIVE_MODEL_BASE_URL`、`PRIVATE_AI_LIVE_MODEL_NAME`、`PRIVATE_AI_LIVE_MODEL_API_KEY` 覆盖。
- 模型工件缺失或哈希不一致会直接中断启动流程，不允许“部分可用”的模型运行时。
- PowerShell 脚本使用 `Set-StrictMode -Version Latest` 与 `ErrorActionPreference = 'Stop'`，确保未定义变量或命令失败立即中止。

## 5. 适用性说明

该仓库没有传统意义上的“应用配置文件”（如 JSON/YAML 形式的 settings 文件），而是将配置分散在 Docker Compose profile、`.env`、PowerShell 脚本、TypeScript 常量与 `process.env` 中，并通过严格的归一化与断言函数保证一致性。因此本类别适用于此仓库，但属于“轻量级、多边界分层”的配置体系。
