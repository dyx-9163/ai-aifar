模块由两部分组成：`compose.yaml` 定义三个互斥的 Docker service（`llama-cpu`、`llama-hybrid`、`llama-gpu`），分别基于 `ghcr.io/ggml-org/llama.cpp:server` 与 `server-cuda` 镜像，通过 `--profile` 选择；所有服务将宿主 `127.0.0.1:8080` 映射到容器内 `0.0.0.0:8080`，并以只读卷挂载 `../models/` 下的两个 GGUF 文件（文本模型与多模态投影）。`.env.example` 提供 `LLAMA_PARALLEL`、`LLAMA_CTX_SIZE`、`LLAMA_N_PREDICT`、`LLAMA_GPU_LAYRBDS_HYBRID` 等可调参数。PowerShell 脚本层（`runtime-common.ps1` + `start/status/stop/verify-model.ps1`）封装 Docker Compose 调用、端口占用检查、SHA256 模型工件校验、运行中实例所有权判定（仅允许一个 `llama-{gpu,hybrid,cpu}` 容器绑定 `127.0.0.1:8080`），以及健康探针（依次调用 `/health`、`/v1/models`、`/props`、`/slots` 并断言返回结构）。`start-model.ps1` 默认尝试 `gpu` profile，若检测到 OOM/CUDA 失败则自动回退一次到 `hybrid` profile。依赖方向单向：脚本 → Docker Compose → llama.cpp 容器 → 本地 HTTP 端点，不反向被宿主进程管理。
