## 1. 整体方法：以结构化结果 + 事件流替代异常传播

本仓库是一个 Electron 桌面应用，采用 **主进程 / Worker / 渲染进程** 多进程架构。错误处理的核心思想是：**不依赖 `throw` 跨进程传播**，而是在每个边界把错误归一化为结构化的结果对象或事件，再通过 IPC/消息通道向上汇报。

- 工具调用层：`src/shared/toolProtocol.ts` 定义了统一的 `AgentToolResult`（`status: 'success' | 'error' | 'cancelled' | 'approval-required'`）和 `AgentToolError { code, message, retryable }`，所有工具执行器必须返回该类型，禁止抛出原始异常。
- 模型连接层：`src/shared/domain.ts` 定义 `ModelConnectionResult` 联合类型（`ok: true/false` + 区分 `connected` / `concurrency-warning` / `slots-unverified` / `offline` / `model-mismatch`），`inspectModelConnection` 把所有网络/解析失败映射为这些状态，而不是抛错。
- 请求-应答层：`src/main/agentRequestBroker.ts` 的 `AgentReply = { ok: true; data? } | { ok: false; error: string }`，超时、端口不可用等全部转为 `reject(new Error(...))`，由调用方按 Promise reject 处理。
- 工作线程层：`src/agent/worker.ts` 通过 `turn.failed` 事件携带 `error` 字符串，并把错误持久化到数据库的 `TurnRecord.error` 字段。

| `src/agent/tools/toolRouter.ts` | 工具路由入口，捕获所有 executor 抛出的异常并转为 `AgentToolResult.status === 'error'`；同时实现读/写信任策略，拒绝时返回 `deny` 策略 |

| `src/agent/agentLoop.ts` | 使用 `AbortSignal` 控制取消，通过 `throwIfAborted(signal)` 在每步检查后抛出 `DOMException('AbortError')` |

| `src/main/agentRequestBroker.ts` | 封装 Agent 请求生命周期，超时、postMessage 失败、disconnect 都转为 Promise reject |
| `src/shared/redaction.ts` | `safeErrorText` / `redactSensitiveText` 负责从错误信息中剔除 API Key、Bearer Token 等敏感内容 |
| `src/shared/operationErrors.ts` | 集中存放业务级“操作被阻止”的常量错误消息（如删除有活跃 turn 的聊天/分组） |

## 3. 架构约定与设计决策

### 3.1 工具调用：结果优先于异常
`toolRouter.executeAgentToolCall` 注释明确声明：“Normalize every failure into a structured `AgentToolResult`, so callers never receive raw exceptions or unclassified text.” 所有工具执行器被 `try/catch` 包裹，异常经 `toToolError` 转换为 `AgentToolError` 后返回。调用方根据 `result.status` 分支处理 success / error / cancelled / approval-required，而不是 try/catch。

### 3.2 模型连接：返回结果而非抛错
`inspectModelConnection` 对每次 I/O 都 `try/catch`，并在 `signal.aborted` 时重新抛出以便上层识别取消；其他情况一律返回 `ModelConnectionResult` 的某个具体变体。这使连接测试可以安全地用于 UI 设置页而不会崩溃。

### 3.3 取消语义：`AbortSignal` + `throwIfAborted`
多处出现 `throwIfAborted(signal)` 辅助函数（`agentLoop.ts`、`worker.ts`），在每次 await 之后检查 `signal.aborted`，若已取消则抛出 `DOMException('Turn was cancelled.', 'AbortError')`。`withExplicitAbort` 包装 Promise，监听 abort 事件并 `reject(signal.reason ?? new DOMException(...))`。取消不是普通错误，而是通过信号机制快速中断长任务。

### 3.4 跨进程错误：Promise reject + 结构化 reply
- `AgentRequestBroker.request` 返回 Promise，未连接时 `reject(new Error('Agent runtime is not ready.'))`，超时时 `reject(new Error('Agent request timed out after ...ms.'))`。
- Worker 侧 `handlePortMessage` 统一 `try/catch`，成功走 `postReply(requestId, true, data)`，失败走 `postReply(requestId, false, undefined, safeErrorMessage(error))`。
- 渲染进程通过 `AgentReply.ok` 判断成功与否，错误文本经过 `safeErrorText` 脱敏后再传给 UI。

### 3.5 错误持久化与展示
- 失败的 turn 通过 `database.failTurn(turnId, now(), message)` 持久化，`TurnRecord` 自带 `error?: string` 字段。
- 运行时状态 `ThreadRuntimeState` 也带 `error?: string`，`core.ts` 的 `reduceCurrentRuntime` 在 `turn.failed` 时将其写入。
- 业务级“操作被阻止”（如删除活跃 thread/group）直接 throw 字符串常量（`ACTIVE_THREAD_DELETE_ERROR` / `ACTIVE_GROUP_DELETE_ERROR`），由调用方 catch 后展示给用户。

### 3.6 安全约束：错误信息脱敏
所有可能包含密钥的错误路径最终都会经过 `safeErrorText(error, [profile.apiKey], 500)`，它会把精确匹配的 secret、JSON/URL 编码变体、以及 `Authorization: Bearer ...`、`bearer <token>` 等模式替换为 `[REDACTED]]`，并截断到 500 字符。这是防止日志/UI 泄露凭据的统一防线。

## 4. 约定与约束总结

1. **工具执行器不得抛出原始异常**：必须返回 `AgentToolResult`，由 `toolRouter` 统一捕获并转成 `status: 'error'`。
2. **网络/IO 错误不向上传播异常**：改用 `ModelConnectionResult` 等结构化结果，调用方通过 `ok` 字段判断。
3. **跨进程错误统一走 `AgentReply`**：Worker 侧 catch 后 `postReply(ok=false, error=脱敏后的字符串)`，主进程 `AgentRequestBroker` 再转为 Promise reject。
4. **取消通过 `AbortSignal` 表达**：不在正常错误流里混入取消；所有异步步骤后调用 `throwIfAborted` 或 `raceWithAbort`。
5. **错误信息必须脱敏**：任何可能暴露 API Key、Bearer Token 的错误文本都要经 `safeErrorText` 处理后再持久化或发送到渲染进程。
6. **业务级“不允许操作”用常量字符串错误**：集中在 `operationErrors.ts`，便于 i18n 或测试断言。
7. **Turn 状态机显式表达失败**：`TurnRecord.status` 可以是 `failed` / `cancelled` / `interrupted`，`error` 字段保存人类可读原因，`incomplete` 标记未完成的内容。
8. **没有使用 `try/catch` 之外的全局错误中间件**：错误处理是内联在每个边界（工具路由、模型连接、请求代理、worker 顶层 catch），没有统一的 express-style 中间件或全局 `unhandledRejection` 处理器。
