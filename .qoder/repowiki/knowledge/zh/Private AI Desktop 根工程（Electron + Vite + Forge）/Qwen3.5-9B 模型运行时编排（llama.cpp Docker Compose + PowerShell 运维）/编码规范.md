- 所有 Compose 操作统一通过 `Invoke-ModelCompose` 封装，固定传入 `-f compose.yaml -p ai-aifar-model --env-file .env` 以保证项目隔离与环境变量加载一致。
- 对模型工件采用“文件名 + 字节长度 + SHA-256”三重比对进行完整性校验，缺失或哈希不匹配直接抛出异常阻止启动。
- 运行期健康检查按固定顺序依次调用 `/health` → `/v1/models` → `/props` → `/slots`，并通过专用 `Assert-*` 函数断言响应字段语义（如 status='ok'、data 数组存在、total_slots 为正整数、slots id 唯一等）。
- Profile 参数使用 PowerShell `[ValidateSet('gpu','hybrid','cpu')]` 进行白名单校验，避免非法输入进入 Compose 命令。
- 启动流程遵循“先检测已有 owned 容器并停止 → 检测端口可用 → 拉起新 profile → 轮询健康直至超时”的顺序，确保同一端口上不会并发运行多个实例。
- GPU profile 启动失败时自动采集容器状态与日志，匹配 OOM/CUDA 错误模式后降级到 hybrid profile，形成内置的回退策略。
